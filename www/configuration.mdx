# Configuration

## The config file

The config file lives at the repository root and is always named `conform.config.ts`:

```ts title="conform.config.ts"
import { defineConfig } from "@adistack/conform";

export default defineConfig({
  preset: "package", // required and must not be empty
  // plugins: [],    // optional: append your own plugins
  // rules: {},      // optional: override preset rules
});
```

- A missing file or an empty `preset` produces `no-config` and exits with code 2.
- An unknown preset name produces `preset-not-found` and exits with code 2.

## Override levels

Each rule override accepts a severity string. Pick one of these three options:

```ts
rules: {
  "biome/format-script": "warn", // soften a failure into a warning
  "github/dependabot": "off",    // skip the rule entirely
  "husky/hook": "error",         // harden a warning into a failure
}
```

## Override params

To change rule behavior, use a flat object. Params sit next to `level`, and `level` is optional:

```ts
rules: {
  // Keep the default level and change only the params.
  "gitignore/excludes": {
    file_expressions: ["node_modules", ".env*"],
  },
  // Change both the level and the params.
  "husky/hook": {
    level: "error",
    hooks: [{ file: ".husky/pre-commit", contains: "bun run format" }],
  },
}
```

## How overrides behave

- `off` skips the rule entirely.
- `warn` demotes a failure to a warning. A pass stays a pass.
- `error` promotes a warning to a failure. A pass stays a pass.
- An unknown string such as `"silent"` fails the rule with `Invalid severity`. Conform fails closed instead of ignoring the typo.
- Invalid params fail the rule with `Invalid params`. The rule body never runs.

## Full example

```ts title="conform.config.ts"
import { defineConfig } from "@adistack/conform";

export default defineConfig({
  preset: "package",
  rules: {
    "biome/format-script": "warn",
    "github/dependabot": "off",
    "gitignore/excludes": {
      file_expressions: ["node_modules", ".env*"],
    },
  },
});
```

## Add your own plugin

You can append a custom plugin and tune its rules in the same file:

```ts title="conform.config.ts"
import { defineConfig } from "@adistack/conform";
import { myPlugin } from "./my-plugin.ts";

export default defineConfig({
  preset: "package",
  plugins: [myPlugin],
  rules: { "my-plugin/my-rule": "error" },
});
```

The plugin authoring guide is in [Authoring](/authoring).
