# Authoring

Every rule must belong to a plugin. There is no standalone `defineRule`.

## Step 1: Create a plugin

A plugin is a container with an ID and a context factory. The factory receives a Target and returns the helpers your rules need:

```ts
import { definePlugin } from "@adistack/conform";
import type { Target } from "@adistack/conform";

export const myPlugin = definePlugin({
  id: "my-plugin",
  context: (target: Target) => ({
    fileExists: (p: string) => target.fileExists(p),
    readFile: (p: string) => target.readFile(p),
  }),
});
```

The context factory runs once per rule invocation.

## Step 2: Add a rule

Each rule performs exactly one check. A rule requires an `id`, a `domain`, a `name`, and a `test` function:

```ts
import { DOMAIN, Status } from "@adistack/conform";
import { type } from "arktype";

myPlugin.defineRule({
  id: "readme",
  domain: DOMAIN.DOCUMENTATION,
  name: "README.md exists",
  test({ context }) {
    return context.fileExists("README.md")
      ? Status.pass()
      : Status.fail("README.md not found");
  },
});

// A rule with params:
myPlugin.defineRule({
  id: "hook-pattern",
  domain: DOMAIN.DEV_ENVIRONMENT,
  name: "hook has pattern",
  files: [".husky/pre-commit"],
  params: type({ pattern: "string" }),
  test({ context, params }) {
    const text = context.readFile(".husky/pre-commit") ?? "";
    return text.includes(params?.pattern ?? "")
      ? Status.pass()
      : Status.fail("pattern missing");
  },
});
```

Field rules:

- `id`, `domain`, `name`, and `test` are required.
- `domain` must be one of `DOMAIN.*`. There is no plugin-level default.
- `files` defaults to `[]` and only affects display grouping.
- `test` receives `{ context, params }` and returns `Status.pass()`, `Status.warn()`, or `Status.fail(message)`.
- If params are invalid, Conform fails the rule before `test` runs.

## Step 3: Create a preset

A preset combines plugins with default rule settings. Use the curried form with `as const` so rule params are type-checked:

```ts
import { definePreset } from "@adistack/conform";
import { biome } from "@/plugins/biome.ts";

export default definePreset([myPlugin, biome] as const)({
  name: "acme",
  description: "Acme org defaults",
  rules: {
    "my-plugin/readme": "error",
    "biome/dev-deps": "warn",
  },
});
```

- Save the file as `src/presets/acme.ts` and reference it with `preset: "acme"`.
- The object form `definePreset({ name, description, plugins, rules })` is also accepted.

## Use the preset

```ts title="conform.config.ts"
import { defineConfig } from "@adistack/conform";

export default defineConfig({
  preset: "acme",
  rules: { "my-plugin/readme": "off" },
});
```

## Common pitfalls

- A `pass` result is never coerced. An `error` override only affects `warn` and `fail` results, which allows intentional suppression.
- An unknown `level` string fails the rule. It is not ignored.
- Rules must read files through Target. They must not use bare `fs`.
- The project requires Bun and strict TypeScript with `verbatimModuleSyntax` enabled.
