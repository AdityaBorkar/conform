# Monorepo

## When to use it

- If your repository has one package, use `defineConfig`. See [Configuration](/configuration).
- If your repository has many workspace packages, use `defineMonorepoConfig` as described here.

Conform detects the config shape automatically, so no extra flag is needed.

## Define the mapping

Keys are package directories. Values are normal single-package configs:

```ts title="conform.config.ts"
import { defineMonorepoConfig } from "@adistack/conform";

export default defineMonorepoConfig({
  ".": { preset: "package" },
  "packages/app": { preset: "package" },
  "packages/lib": {
    preset: "package",
    rules: { "biome/dev-deps": "off" },
  },
});
```

The mapping follows four rules:

- Keys may be relative (recommended) or absolute.
- Every discovered workspace package needs a key. A missing key is an error.
- Every key must match a discovered workspace. An extra key is an error.
- The root `package.json` must declare a `workspaces` field. A missing field is an error.

## Run a check

Run the same command from the repository root:

```sh
bunx conform check        # check every workspace package
bunx conform check --json # print JSON with one entry per package
```

Conform prints one block per package, then an aggregated summary:

```
━━ /repo/packages/app (package) ━━
Build & Tasks
  ...

Summary: 64 passed · 4 warned · 2 failed across 3 packages
```

The JSON shape is:

```json
{
  "path": "/abs/repo",
  "outputs": [{ "preset": "package", "path": "/abs/repo/packages/app", "summary": {} }],
  "summary": { "pass": 90, "warn": 3, "fail": 2 }
}
```

## Errors (all exit with code 2)

| Code | Meaning |
|---|---|
| `monorepo-no-workspaces` | The root `package.json` has no `workspaces` field. |
| `monorepo-unconfigured-package` | A workspace package has no key in the config. |
| `monorepo-extraneous-package` | A config key matches no workspace package. |
| `monorepo-config-error` | A config entry is missing its `preset`. |

Result codes match single-package mode: `0` means everything passed, `1` means at least one package failed, and `2` means warnings only or a config error.

Agent hint: `expandWorkspaces` reads `package.json:workspaces`, expands globs with `Bun.Glob`, keeps directories containing `package.json`, and sorts the result. `resolveMonorepoPackages` then matches config keys against that list.
