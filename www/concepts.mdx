# Concepts

## Everyday terms

| Term | Meaning |
|---|---|
| **Preset** | A named collection of checks. Example: `package`. Each preset lives in `src/presets/*.ts`. |
| **Plugin** | A group of related rules inside a preset. Example: `biome` or `husky`. |
| **Rule** | A single atomic check. Example: `biome/dev-deps`. Each rule has exactly one job. |
| **Domain** | A display group for rules, such as `Build & Tasks`. It only affects output grouping. |
| **Files** | The files a rule cares about, such as `biome.json`. An empty list means the rule is not file-scoped. |
| **Target** | A filesystem view of your repository. Rules may only read files through Target, never through raw `fs`. |
| **Status** | A rule verdict: `pass`, `warn`, or `fail`. Rules return it with `Status.pass()`, `Status.warn()`, or `Status.fail()`. |
| **Drift** | Any deviation from the preset. Drift is any `warn` or `fail` result. |

Use `Preset` (not `preset`), `Plugin` (not `RuleSet`), and `domain` (not `group`).

## Configuration terms

| Term | Meaning |
|---|---|
| **RuleLevel** | The severity you request: `off`, `warn`, or `error`. `error` becomes `fail` and `off` skips the rule. |
| **RuleConfig** | A single override. It is either a string such as `"warn"` or a flat object such as `{ level, ...params }`. There is no `params` wrapper. |
| **ConformConfig** | The shape of `conform.config.ts`: `{ preset, plugins?, rules? }`. |
| **ConformOutput** | The `--json` payload: `{ preset, path, results, summary }`. |
| **presetResolver** | The function that finds a preset by name in `src/presets/<name>.ts`. |

Agent hint: the canonical definitions live in `/CONTEXT.md`. Use these exact terms in code and prompts.

## How a check runs

Every check follows the same four steps:

```
1. Load config   -> read conform.config.ts
2. Find preset    -> resolve the preset by name
3. Merge          -> combine preset rules with your rules
4. Run each rule  -> collect pass, warn, and fail results
```

- `off` skips the rule without running it.
- An unknown `level` fails the rule without running it. Conform fails closed.
- Invalid `params` fail the rule without running it.
- A `pass` result is never rewritten, even by an `error` override. This allows intentional suppression.

## Exit codes

A failure always outranks a warning.

| Code | Meaning |
|---|---|
| `0` | Every rule passed. |
| `1` | At least one rule failed, or `--json` was combined with `--group`. |
| `2` | Only warnings, or `no-config`, `preset-not-found`, or monorepo errors (`monorepo-no-workspaces` / `monorepo-unconfigured-package` / `monorepo-extraneous-package` / `monorepo-config-error`). |

Output icons: `✓` means pass, `⚠` means warn, and `✗` means fail.
