# Plugins

## How plugins work

- A preset contains plugins, and each plugin contains rules.
- Every rule reads the repository through Target (`fileExists`, `readFile`, `readJson`, `packageJson`).
- You can tune any rule with `"plugin-id/rule-id": "off" | "warn" | "error"` or with a flat `{ level?, ...params }` object.

## The 9 plugins

### `package-json`

This plugin inspects `package.json`.

| Rule | Params | Check |
|---|---|---|
| `structure` | — | Are name, version, and license valid? |
| `entry-point` | `fields` (default: main, module, exports) | Is at least one entry field defined? |
| `build-script` | `scripts` (default: prepare, build) | Is a build script defined? |
| `files-or-npmignore` | `file_expressions` | Is a files field or .npmignore present? |
| `no-install-hooks` | `scripts` | Are install hooks absent? |
| `required-fields` | `fields` | Are all listed fields present? |
| `typecheck` | `scripts` | Is a typecheck script defined? |
| `no-prepublish` | `scripts` | Is the deprecated prepublish script absent? |

### `biome`

This plugin checks lint and formatting. Its domain is Style & Validation.

| Rule | Check |
|---|---|
| `dev-deps` | Is Biome in devDependencies? |
| `config-exists` | Is biome.json or biome.jsonc present? |
| `config` | Does biome.json match the expected config? The `config` param is shallow-merged over it. |
| `lint-script` | Does a lint script run Biome? |
| `format-script` | Does a format script run Biome? (warn) |

### `typescript`

This plugin checks the TypeScript setup. Its domain is Code Quality.

| Rule | Check |
|---|---|
| `deps` | Is TypeScript in devDependencies or peerDependencies? |
| `tsconfig` | Is tsconfig.json present? |
| `compiler-options` | Do the compiler options match the expected strict set? The `compilerOptions` param is shallow-merged over it. |

### `husky`

This plugin checks git hooks. Its domain is Dev Environment.

| Rule | Check |
|---|---|
| `dev-deps` | Is Husky in devDependencies? |
| `hooks-dir` | Is the .husky/ directory present? |
| `prepare-script` | Does the prepare script call Husky? |
| `hook` | Does every configured hook file exist and contain the expected text? (`hooks: [{ file, contains }]`) |

```ts
rules: { "husky/hook": { hooks: [{ file: ".husky/pre-commit", contains: "bun run format" }] } }
```

### `docs`

This plugin checks repository documentation.

| Rule | Check |
|---|---|
| `readme` | Is README.md present and non-empty? |
| `changelog` | Is a CHANGELOG file present? (warn) |
| `contributing` | Is a CONTRIBUTING file present? (warn) |
| `license` | Is a LICENSE file present? |
| `security-md` | Is a SECURITY.md file present? (warn) |

### `gitignore`

| Rule | Check |
|---|---|
| `exists` | Is .gitignore present? |
| `excludes` | Does .gitignore contain every configured `file_expressions` entry? |

### `github`

This domain is GitHub Configuration.

| Rule | Check |
|---|---|
| `ci-workflow` | Is a ci, test, build, or check workflow present? |
| `release-workflow` | Is a release, publish, or deploy workflow present? (warn) |
| `ci-lint` | Does the CI workflow run lint? (warn) |
| `ci-typecheck` | Does the CI workflow run typecheck? (warn) |
| `dependabot` | Is Dependabot or Renovate configured? (warn) |
| 25 more | CODEOWNERS, PR checks, branch protection, Actions lockdown, and secret scanning. Most require `CONFORM_GITHUB_API_TOKEN`. The full list is in [Presets](/presets). |

### `zed`

| Rule | Check |
|---|---|
| `dir` | Is the .zed/ directory present? |
| `settings-exists` | Is .zed/settings.json present? |
| `settings` | Do the settings match the expected values? |

### `bun`

| Rule | Check |
|---|---|
| `bunfig-exists` | Is bunfig.toml present? |
| `bunfig-content` | Does bunfig.toml contain the expected values? Full defaults live in `src/presets/package.ts`. |

Full param defaults live in `src/plugins/*.ts` (`DEFAULT_*` constants) and `src/presets/package.ts` (`BIOME_CONFIG`, `BUNFIG_CONFIG`, `TSCONFIG_COMPILER_OPTIONS`, `ZED_CONFIG`). Agent hint: preset defaults live in `src/presets/package.ts`; per-rule fallbacks use `??` defaults inside each `test` in `src/plugins/*.ts`.
